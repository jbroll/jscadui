# Parts catalog: standard hardware from the test corpus

Status: approved design, 2026-10-01. Working document; delete before merge
after folding the lasting parts into the permanent docs.

## Goal

Users and the chat agent can pull standard hardware (nuts, screws, washers,
ball bearings, stepper motors, and later inserts, pulleys, belts, rails,
extrusions) into their own models as read-only parametric parts. The parts come
from the OpenSCAD libraries already in the transpiler test corpus. Each part in
the catalog is vetted: its dimensions are checked against the published
standard, it has a doc entry and a thumbnail, and its license is shown.

## Decisions

- **Parts are called, not copied.** A part is a function the user's model calls
  after a `require` (JS) or `use`/`include` (SCAD). Library files never enter the
  project.
- **Library-native APIs.** Each part keeps its library's own call and size
  scheme: `nut(M3_nut)` from NopSCADlib, `nut("M3")` from BOSL2. A catalog
  index describes them. Each family has at most one `preferred` entry, which the
  agent uses by default and the browser lists first. A unified facade, if ever
  wanted, sits on the preferred entries.
- **All licenses except non-commercial**, each labeled. The agent prefers a
  permissive part when two are equivalent. CC-BY-NC (the `gears` suite) is out.
- **Both languages.** SCAD files use the libraries through `OPENSCADPATH`-style
  includes; JS files `require` the same `.scad` path and get clean names.
- **Vetting** means a dimension check against the standard, a generated doc
  entry, and a thumbnail, all produced from one record per entry.

## 1. Library tree and resolution

### Tree

Each library is deployed once, unpatched, in the layout OpenSCAD expects:

```
jscad.rkroll.com/libs/NopSCADlib/vitamins/nuts.scad
jscad.rkroll.com/libs/BOSL2/screws.scad
```

`scripts/fetch-deps.js` already clones each library at a pinned commit
(`scripts/deps/manifest.json`). Each catalog library gets a second destination,
`apps/jscad-web/libs/<Library>/`, filled from the same clone, with the upstream
LICENSE file copied alongside. The test corpus keeps its own patched copies
(BOSL2 includes rewritten to `lib/`, scad-utils copied into several suites);
restructuring the suites around `/libs/` is out of scope.

`apps/jscad-web/build.js` copies `libs/` into the build as it does `examples/`.
The app host serves `/libs/` with `Access-Control-Allow-Origin: *`, because the
frame on `jscad-run.rkroll.com` has an opaque origin. `/libs/` is gitignored like
the fetched corpus.

### Resolution

The same library path works from both languages:

- **SCAD.** `include <NopSCADlib/vitamins/nuts.scad>` tries the including file's
  directory first, then `<app origin>/libs/`. The new candidate goes in
  `includeCandidates` (`apps/jscad-web/src_frame/scadResolve.js`), after the
  existing per-suite library fallback, and applies to project files
  (`http://project.local/...`) as well as app-origin files.
- **JS.** `require('NopSCADlib/vitamins/nuts.scad')`: a bare specifier whose
  first segment names a deployed library resolves to `<app origin>/libs/`
  instead of jsDelivr. The library-name list is generated at build time from the
  catalog and baked into the frame.

The scad handler already skips re-reading app-origin files until a redeploy
(`scadHandler.js`, `chainUnchanged`), so library files are fetched once per
session and never appear in the project file map or the agent's per-turn
context.

### Pinning

A library under `/libs/` changes only when its pin moves in
`scripts/deps/manifest.json`. The catalog checks (section 2) gate that commit.

## 2. Catalog record and generated outputs

### Package

New workspace package `packages/parts`:

```
packages/parts/
  catalog/<library>/<entry>.json   one record per entry, hand-written
  thumbs/<entry-id>.png            committed, regenerated by the CI job
  bin/check.js                     dimension checks and size sweep
  bin/render.js                    thumbnails
  bin/build.js                     catalog.json, agent docs, library list
```

### Record

```json
{
  "id": "nopscadlib/nut",
  "family": "nut",
  "preferred": true,
  "library": "NopSCADlib",
  "license": "GPL-3.0",
  "file": "NopSCADlib/vitamins/nuts.scad",
  "call": "nut",
  "summary": "ISO 4032 hex nut, optionally nyloc.",
  "sizes": { "list": "nuts" },
  "options": { "nyloc": "add the nylon insert", "brass": "brass colour" },
  "example": "nut(M3_nut, {nyloc: true})",
  "checks": [
    { "args": ["M3_nut"], "size": [6.35, 5.5, 2.4], "tol": 0.05, "source": "ISO 4032 M3" }
  ]
}
```

Hand-written: family, preferred, summary, option meanings, example, and the
standard dimensions with their source. Derived:

- **Signature** (parameter names, order, defaults) from the transpiler's `$meta`
  export (section 3).
- **Size names.** `sizes.list` names a library list variable; the generator
  requires the file and keeps each exported variable whose value is an element of
  that list (same array object), giving `M2_nut`, `M3_nut`, ... Libraries keyed
  by spec strings list them: `"sizes": { "values": ["M2", "M2.5", "M3"] }`.

`checks[].size` is the axis-aligned bounding box `[x, y, z]` in mm of the part
built with `args`, in its default orientation. `tol` is absolute, in mm.

### Outputs

1. **Checks** (`bin/check.js`). Transpiles each entry from
   `apps/jscad-web/libs/` with the same resolution rules as the frame, calls it
   through its clean JS export, and compares each `checks` bounding box. It also
   builds every listed size once and fails on any that throws or returns empty
   geometry. It records transpile and build time per entry. One entry runs
   locally (`node bin/check.js nopscadlib/nut`); the full catalog runs as a
   simple-ci job on the GPU host.
2. **Thumbnails** (`bin/render.js`). Renders each entry's first check size with
   `packages/agent-loop/eval/render.js` into `thumbs/`. Runs in the same CI job.
   Committed, because they change only when a pin or the transpiler moves.
3. **`catalog.json`** (`bin/build.js`, called from `apps/jscad-web/build.js`).
   Every record merged with its signature, size names, thumbnail path, measured
   dimensions and timings. The parts browser reads it.
4. **Agent docs entries** in the format `packages/agent-loop/src/docs.js`
   serves, plus the generated "Parts" prompt block (section 4).
5. **Library-name list** for the frame's bare-require mapping.

An entry is admitted when its checks pass in CI and a person has looked at its
thumbnail.

## 3. Transpiler clean exports

### Surface

Every transpiled file exports, beside `main` and `getParameterDefinitions`:

- **Modules** as plain functions returning geometry. `washer(M3_washer)` calls
  `washer_$m({type: M3_washer})()`.
  - Positional arguments map to parameter names, which the transpiler knows.
  - A trailing plain object holds named arguments:
    `nut(M3_nut, {nyloc: true})`. SCAD values are never plain objects, so this
    is unambiguous.
  - Keys starting with `$` pass through as special variables (`{$fn: 64}`),
    through the existing `$$sv` path.
  - `children` takes geometry or an array of geometry; the wrapper wraps each in
    the thunk the module expects. `washer(M3_washer, {children: nut(M3_nut)})`
    stacks the nut on the washer.
- **Functions** with the same argument rule, calling `_$f` or `_$f$obj`.
- **Variables** by value. Those the transpiler emits as thunks because they read
  special variables (NopSCADlib's `layer_height`) become getters.
- **Clashes.** When a module, function and variable share a name, the bare name
  goes to the module, then the function, then the variable. Every function is
  also under `fn` and every variable under `vars`. SCAD names equal to `main`,
  `getParameterDefinitions`, `fn`, `vars`, `$meta` or `$scad` get no bare name.
- **Includes** re-export their clean names, as they re-export suffixed names
  today. `use` imports are not re-exported, matching SCAD.

### Metadata

`$meta` lists each public name with its kind (`module`, `function`,
`variable`) and, for modules and functions, its parameters in order with
defaults as source text: `{name: 'nyloc', default: 'false'}`.

### Commits

Each follows `packages/openscad/CLAUDE.md`: `npx vitest run`, a GPU run, and a
new section in `MODEL_COMPARISON_BASELINE.md`.

1. **Add the clean surface and `$meta`** beside today's exports. Unit tests cover
   positional and named arguments, children, `$` variables, getters, clashes and
   include re-exports. No existing model reads the new names, so the baseline
   must not move.
2. **Move suffixed names under `$scad`** and point generated `use` and
   include re-export code at `_ns0.$scad.x_$m`. Before the change, list every
   reader of suffixed exports outside the transpiler (frame, worker, tests, e2e
   helpers) and update them in the same commit.

### Docs

The export interface goes in `packages/openscad/ARCHITECTURE.md`; requiring a
`.scad` from JS, and the catalog, go in a new `apps/jscad-web/docs/user-manual.md`
(the app has only `architecture.md` today).

## 4. Agent and parts browser

### Agent (`packages/agent-loop`)

- Generated part entries join the index the `docs` tool searches.
  `docs('nut')` returns the nut entries, preferred first, each with its require
  line, signature, size names, options, license and measured dimensions.
- The prompt gets a generated "Parts" block: each family with its preferred
  entry's require line and call, and three rules: use a catalog part for
  standard hardware instead of modeling it; prefer a permissive license when two
  parts are equivalent; never copy library files into the project.
- The eval executor (`eval/executor-child.js`) has no `.scad` handler. It gets
  one, with the `/libs/` mapping pointed at the local `apps/jscad-web/libs`,
  since the crt sandbox has no network.
- New fixtures: a NEMA 17 mount plate with M3 screws (requires the catalog
  stepper and screws; hole spacing matches the part's measured dimensions) and a
  608 bearing holder (bore matches the bearing's outer diameter).

### Parts browser (`apps/jscad-web`)

- A panel beside the demo browser. Families as thumbnail cards, preferred first,
  with a license badge.
- Entry view: summary, signature, size picker, options with meanings, measured
  dimensions, license, example.
- **Insert** adds the require (`.js`) or `use`/`include` (`.scad`) line at the
  top of the current file if missing and puts the call at the cursor.
- Reads `catalog.json` only.

## 5. First entries

| Family | NopSCADlib (GPL-3.0) | BOSL2 (BSD-2) |
|---|---|---|
| Nut | `nut` | `nut` |
| Screw | `screw` | `screw` |
| Washer | `washer` | none |
| Ball bearing | `ball_bearing` | `ball_bearing` |
| Stepper | `NEMA` | `nema_stepper_motor` |

`preferred` is set per family after the first CI run. BOSL2 is permissive but
pulls about 60k lines through `std.scad`; the recorded transpile and build times
decide whether that is acceptable in the browser.

## 6. Order of work

Each step lands on its own and is verified before the next.

1. Transpiler commit 1: clean surface and `$meta` (GPU-verified).
2. `/libs/` tree, SCAD fallback, JS bare-require mapping, and an e2e smoke check
   that includes a NopSCADlib nut from a project `.scad` and requires it from a
   project `.js` on the live host.
3. `packages/parts`: generator, `check.js`, thumbnails, CI job, first entries.
4. Transpiler commit 2: `$scad` move, gated by the GPU run and the parts checks.
5. Agent: executor `.scad` support, docs entries, prompt block, fixtures.
6. Parts browser.
