# Demo Provider + TOS Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship demo provider with server-held keys plus mandatory TOS gate as one feature.

**Architecture:** Reuse the 2026-10-01 record format and route shapes: shared `chatLog.js` module used by launcher and production relay, new `shared.json`-driven demo routes with a file-persisted meter, and a client consent module gating every Send.

**Tech Stack:** Node express relay (plain JS + JSDoc, tsc allowJs), vitest, browser localStorage consent, existing `@jscadui/agent-loop` providers.

**Spec:** `docs/superpowers/specs/2026-10-15-demo-provider-tos-design.md` (plus background `docs/superpowers/specs/2026-10-01-chat-logging-and-shared-keys-design.md` for record format and meter math)

## Global Constraints

- Client demo credential is exactly `demo-limited-free`; server ignores its value and injects the real key.
- Generic training warning for all models; no per-model training flag or overlay table.
- `localStorage['jscad-ai.tos'] = { version, at, recordOwnChats }` is source of truth; `localStorage['jscad-ai.log']` is derived mirror; divergence → `.tos` wins.
- `TOS_VERSION` bump clears acceptance and re-blocks turns until re-accept.
- Demo turns always logged, no opt-out; own-key turns omit `x-jscad-chat-id` when opted out; custom base URL never logged.
- Headers never written to chat logs.
- Single-ship: Phase 1 + Phase 2 + demo/TOS land together.

## Review Focus

- Demo POST with curl and no chat id still writes a log record with `shared` and `costUsd` — a reasonable person expects no free anonymous bypass.
- Third concurrent demo request from one IP group gets 429 with `Retry-After: 2` — a reasonable person expects the burst bound to hold.
- Month-spent budget refuses with 402 `shared_quota_exhausted` that agent-loop does not retry — a reasonable person expects spend to stop, not loop.
- TOS decline blocks the turn with a quota-style error line, not a dead page — a reasonable person expects to keep reading history.
- Unknown new model id routes by existing `RESPONSES_MODELS`/`MESSAGES_MODELS` sets without a TOS change — a reasonable person expects chat to work, not refuse.
